# Presentation and resource-lifetime audit (#58)

Baseline main: `0c10f2d`. Tests use independent owned-game Windows copies and disposable family/native saves, regular v0.107.1, public-beta v0.111.0, BaseLib 3.4.7 and Spire Legacy 1.0.29. [Issue-specific evidence](adversarial-presentation-evidence.json) records exact DLL/source hashes, seeds, commands, measured outcomes, asset provenance and complete deduplicated diagnostics. Game files, screenshots, native saves and raw receipts remain private. No installed game branch or Workshop/Melty package was changed.

## Confirmed defects and fixes

- **#85, crab facing:** paid left-target Attacks changed the native Body X scale to -0.28 while the visible Knight remained +1.1386138. The heir now follows native body facing; its own animation frame alignment preserves that sign. Badges and readable banner text are separate and remain unmirrored.
- **#64, late ribbon:** the ribbon was under native `Sprites`, which fades in over a second and shrinks. A moving native trail fixture measured alpha 0.049 at 10 ms and 0.965 at 659 ms, with a changing world scale. All three original trail scenes now place the ribbon under sibling `Trails`; it remains alpha 1 and unscaled during that same movement. The crest retains its native fade, and native trail fade-out/cleanup remains intact. The authoring script and provenance hashes reproduce the changed scenes.
- **#136, missing illustration:** a deliberately missing PNG caused NullReferenceException at `image.IsEmpty()`. Missing/corrupt illustrations now produce a path-bearing InvalidDataException, and temporary SVG/bitmap image buffers are disposed. Disposed cached textures are recreated successfully.
- **#137, shop ownership:** a native paid purchase spent 48 gold and added one card but animated both peers' heirs. Room sprites now carry their owner ID, and the purchase callback animates only that owner's sprite. Final paid callback cases preserve the other heir's animation state.
- **#138, rest-site facing:** slot two's native Spine scale was -1 while the visible Mage remained +5.0773582. A Heir-only response to native `FlipX` mirrors the added sprite while preserving its animation, feet anchor, scale and traits. Knight/Mage and Knight/Ranger pairs pass on both branches.
- **#139, room callback lifetime:** game-over reparenting caused repeated attempts to disconnect a nonexistent ProcessFrame connection. A one-time attachment also failed to resume motion after re-entry. Room motion now connects one stable Callable on TreeEntered and disconnects only if connected on TreeExiting. A live portrait moved between parents twice continues breathing; real rest/shop abandonment for every class no longer emits the previous disconnect error.

## Native coverage and limits of the observations

Each branch exercises all three classes against the actual Kaiser Crab encounter: base/upgraded paid strikes target left and right, spend their normal energy cost and reach Discard. Final tutorial-free effects stages verify correct facing, immediate native ribbon samples, actual energy/map/cookie widgets, original sound routing and Architect effect creation. The native Ironclad identity remains unchanged. These are controlled encounter/card probes, not naturally reached boss victories or physical card-input tests.

The broad lifecycle stages include 24 runs per branch: three crab runs, nine repeated class/trait runs and twelve endings. The repeated runs visit rest, shop and combat, use paid base/upgraded strikes/guards, apply actual hurt, save/resume all three classes, execute rest and paid shop callbacks, and inspect combat victory. Traits combine Dwarfism/Colorblind, Gigantism/Synesthesia and Blue/Nature. All classes also cover startup abandonment, rest/shop abandonment and combat death. Mage plays every death frame and holds the final one; ending sprites retain the correct class and hide the native placeholder. Dedicated later cleanup stages repeat all-class room endings after the subscription fix.

Nine settled resource checkpoints per branch show one heir sprite, no remaining mod sound players and no card-trail nodes. After warm-up, texture entries remain 77 on regular and 74 on beta, orphan counts remain 267, matched-class node counts are unchanged, and native resource counts change by at most two. Process private-memory changes between the last two matched cycles are under 64 MiB. These are finite observations, not a long-duration leak proof. Godot's static-memory monitor returned zero/unavailable, so the memory field uses Process.PrivateMemorySize64; it does not measure resident memory or GPU allocation. Frame-process times are retained without presenting the offscreen lab as a device performance benchmark.

Native two-peer cases cover frozen per-owner banners, contrasting size/color traits, rest-slot direction and paid shop completion callbacks on each branch. The room selection fixture enters both peers concurrently because native debug room changes require synchronization. Purchases invoke the native paid wrapper locally to inspect its owner-specific callback; this does not certify the complete network shop UI action route. No native checksum checks were disabled.

Screenshots at native 1280×800/16:10 settings were inspected for enlarged Mage/rainbow rest presentation, Ranger/paired palette shop presentation and combat-death sprites. Long-name/Manor focus and picker/Ascension coverage remain in #57; Architect ending/dialogue coverage remains in #56. The 51 original presentation assets regenerate without additional changes, and preflight validates their recorded hashes. Release build, 164,053 core assertions and all 20 harness checks pass.

## Diagnostic review and fixture corrections

The initial broad forced-crab stages activated a fresh-profile combat tutorial that assumes ordinary enemy intent widgets. Its native FTUE task failed in the forced encounter. Those full diagnostics are retained; the broad stages are resource/presentation observations, not healthy complete-combat-loop passes. New fixtures mark tutorials complete only in their isolated native save, and final effects/cleanup stages explicitly reject that FTUE error. The forced Act 2 crab in an Act 1 test run can also report unavailable native boss music; audible acceptance and natural campaign audio remain deferred.

The broad logs exposed the real room-motion disconnect defect, now covered by later cleanup stages. Expected invalid-SVG diagnostics from the deliberate negative fixture, native renderer particle limitations, WorkerThreadPool diagnostics and native save cleanup messages remain visible in the evidence; the audit does not claim empty logs. Early fixture errors included using a nonexistent `big` trait ID instead of `large`, counting native audio nodes as mod one-shots, a solo-only state projection after co-op room entry, and entering only one peer into a synchronized room. Corrected fixtures use canonical IDs, scoped audio tags, co-op projection and simultaneous peer entry. An ENet connection timeout was retried only in fresh profiles, without replaying a timed-out mutation.

## Explicit deferrals

Physical Steam Deck/Linux/Proton, audible quality, Steam transport, natural complete campaigns, timed hardware disconnects and extended memory/performance soak remain open device/release validation, including #110. Vulkan/reduced-particle settings, arbitrary locale/UI scale matrices, every noncombat event type, and corrupt WAV/scene/material injection are not passes. Negative asset coverage is invalid SVG, missing PNG and invalid sound role. Existing illustration/code authoring and package/installation audits remain #61/#62. No game-derived art, recordings, DLLs or PCKs are added to this PR.

## Reproduction

Build against owned native assemblies and prepare independently copied private labs using [the harness procedure](adversarial-harness.md). `scripts/run-balance-campaign.ps1 -PresentationAuditChecks` selects the native script; fresh tags containing `effects` or `cleanup` select focused confirmations, while ordinary tags run the broad lifecycle suite. `scripts/run-coop-audit.ps1 -Pair -PresentationChecks` exercises peer ownership; tags containing `ranger` select the second class pair. Supply the required lab/class/branch, new tag, Python runtime and distinct co-op port. Launchers isolate saves, refresh original mod presentation assets and stop only verified copied-game PIDs. `scripts/sts2-presentation-evidence.py` verifies the completed audit tags and exports the compact proof, without tracking the generic generated coverage map or local modlog.
