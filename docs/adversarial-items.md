# Relics, potions and bounded trigger audit (#55)

Baseline: merged main `24c506861e70232c41315dee2122738e028f8858`. The audit used independent owned-game Windows copies, disposable native/family profiles, regular v0.107.1, public-beta v0.111.0, BaseLib 3.4.7 and Spire Legacy 1.0.29. Exact loaded DLL hashes, source checkpoints, seeds, measured effects, complete deduplicated diagnostics and request counts are in [the validated proof](adversarial-items-evidence.json). No personal saves, installed game branches or published packages were changed.

## Confirmed finding and fix

[#128](https://github.com/CapeKid/SpireLegacy/issues/128): native relic cloning shallow-copied Bloodline's first-hit target set and drawn-card cost dictionary. Two Knight/Mage owners with the first-hit Weak trait attacked the same enemy through actual paid card actions: the first owner added 1 Weak, the second added 0. Public-beta clone probes also found shared collections in both Bloodline and Refined Bloodline.

`BloodlineRelic.DeepCloneFields` now calls the native base implementation and creates fresh collections for the new instance. Refined Bloodline inherits the correction. This changes state ownership, without changing card balance or trait amounts. Both branches' clone probes now show isolation from the canonical model and sibling clones. Knight/Mage and Knight/Ranger native two-peer regressions each measure Weak deltas **1, 1** for the owners' first attacks, then **0, 0** for upgraded repeat attacks that turn. Native checksum checks remain enabled, both peers wait for each action's checkpoint, complete visible owner states agree, and family settlement stays isolated.

## Completed coverage

- Every one of the ten family relics: Knight/Mage/Ranger, base and upgraded triggering cards, native reward and merchant acquisition. The 60 cases per branch check exact Block/draw/Vigor/Arcane Charge effects, repeated trigger caps and visible counters, native scalar serialization/replacement and full run save/resume identity. Timed relics advance real solo turns to their thresholds. Fixtures buffer HP and energy to isolate item behavior; these are not balance or campaign-win claims.
- All ten relics stacked together: paid Power/Skill/Attack and exhaust sequences, discard/refill interactions, native turn-end/start transitions, per-turn rearming, persistent combat claims, native mid-sequence counter round trips, removal/reacquisition and subsequent triggering. A newly acquired instance correctly receives a fresh claim; no automatic acquire/remove loop was added.
- Locked/unlocked Chronicle × all three classes × ordinary/Pacifist: 12 native source cases per branch. Each case samples 450 relic rewards, 220 merchant inventories, 1,800 potion rewards and generated potions, and 500 potion merchant inventories. Allowed sets match; class-dependent Pacifist exclusions hold; all three potions remain available; native character pools have no Heir entries. Icons, cached resource paths and formatted descriptions are checked by the source inspectors.
- Empty personal relic bags return native Circlet rewards for Common/Uncommon/Rare. The depleted shared bag used by Antique refreshes from its original pool and grants one Common relic, without an exception. This rejected a suspected starter-grant failure; production acquisition code was left unchanged.
- Every potion × all classes × ordinary/Pacifist/Super Healer × reward/merchant paths: 54 actual queued uses per branch. Exact Block, draw, Poison, Weak, Vigor and capped Mage charges match the descriptions; HP and energy remain unchanged; saved belts preserve identity and slots, and consumed belts become empty.
- Full belts reject acquisition without changing slots. Invalid-target queues cancel without consumption; dead-target cancellation is exercised while another enemy remains alive. Zero-alive-enemy target validity is checked synchronously, before the game can legitimately transition to victory. Two native actions for the same slot produce one use, one effect and an empty slot, retaining neighbouring potions. Native Weak Potion and Block Potion controls exhibit the same cancellation/consumption behavior.
- Nine native controller callback uses per branch cover all three potions/classes, including cancel and confirm of enemy targeting. The fixture counts native `PotionUsedEntry` records, because general model `ExecutionFinished` notifications also run for hooks and cannot prove consumption. Knight/Mage and Knight/Ranger co-op Triune Draught uses affect only their owning player; other owners' hands, resources, Block and belts remain unchanged.

The build passed with no warnings/errors; core checks passed **164,053 assertions**, harness checks passed **20 checks**, and preflight validated **32 sheets / 2,062 rows / 26,477 cells**. Generated generic audit coverage and MODLOG remain ignored; only issue-specific proof is tracked.

## Diagnostics and explicit deferrals

These runs do not have universally clean stderr. The proof retains compatibility-renderer particle warnings, beta WorkerThreadPool `Invalid Task ID` messages, missing native backup deletion diagnostics on private run abandonment, and the deliberate owner-diagnostic fixture. Beta's native executor also logs that intentionally canceled invalid/duplicate potion actions finished in a canceled state; native potion controls reproduce that message while retaining correct belts/effects. Those engine diagnostics were not suppressed or presented as mod fixes. Resource/renderer investigation belongs to #58; platform/release-path investigation belongs to #62.

Physical Steam Deck/Linux input, distribution delivery, disconnect timing and complete campaigns remain device/integration gaps (#110 and #62). Controller callback coverage is not a physical controller pass. Neither tested game branch exposes a supported doubled-potion-effect modifier or Sacred Bark model; doubled effectiveness is explicitly deferred until such a native mechanic exists. Full native saves restart a combat, so scalar mid-sequence persistence is verified separately through native relic serialization/replacement. Co-op cases cover the confirmed starter ownership regression and Triune Draught, rather than every item/trait/peer-count combination; drawn-cost isolation and Refined Bloodline are clone regressions, rather than a second full native combat matrix. These limits are retained in the proof and should not be converted into broader pass claims.

## Reproduction

Build against the owned regular SDK, then use `scripts/run-balance-campaign.ps1 -ItemAuditChecks` with a fresh private lab/profile tag. `scripts/sts2-item-audit.py` selects `relics`, `sources`, `potions`, `relic-edges`, `edges`, `antique`, `controller` or `clones` by tag. Run `scripts/run-coop-audit.ps1 -Pair` with an `items55` or `items55ranger` tag for the two owner pairings. Run `scripts/sts2-item-audit-evidence.py` against the completed private receipts to validate and regenerate the public proof. Never reuse a timed-out mutation request or personal profile. Launch wrappers stop only their exact verified private executable PIDs.
